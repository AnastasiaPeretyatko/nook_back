# Резервные копии базы

Сервер ничего не хранит у себя: всё лежит в базе Neon. Neon сам помнит историю базы **6 часов** (бесплатный тариф) — этого хватит, чтобы откатить свежую ошибку. Если нужна копия «навсегда», или Neon недоступен, или прошло больше 6 часов — нужна **своя копия** в файле. Её делает один скрипт, ничего не удаляя и не меняя в базе.

## Что понадобится

- Клиент PostgreSQL **версии 16 или новее** (программы `pg_dump`, `pg_restore`, `psql`). Проверить: `pg_dump --version`. Нет — на Ubuntu: `sudo apt install postgresql-client`.
- Файл `.env` проекта с `DATABASE_URL` (он уже есть — тот же, что у сервера).

## Сделать копию

```bash
npm run backup
```

(то же самое: `scripts/backup.sh`). Скрипт:

1. берёт адрес базы из `.env` (или из переменной `BACKUP_DATABASE_URL`, если задана);
2. записывает файл `~/nook-backups/nook-ДАТА-ВРЕМЯ.dump` — **вне проекта**, чтобы его нельзя было случайно закоммитить (папку внутри проекта скрипт не принимает). Другая папка: `npm run backup -- /путь/к/папке`;
3. рядом кладёт `…dump.counts` — сколько строк в каждой таблице на момент копии (нужно для проверки при восстановлении);
4. проверяет, что файл читается обратно. Если что-то пошло не так — недописанный файл удаляется.

Ждите до минуты: если база Neon спит, её сначала нужно разбудить. Пароль и адрес база на экран не выводятся.

**Когда делать.** Скрипт никто не запускает сам — только вы. Разумно: раз в неделю и **перед** каждой выкладкой новой версии сервера (в ней могут быть изменения базы).

### Что внутри файла и как его беречь

В копии **вся база**: почты, хеши паролей, дневники, циклы — то есть личные данные. Файл читается только вами (права `600`). Не кладите его в репозиторий, не отправляйте в мессенджеры, не оставляйте на общем компьютере; лучше хранить на зашифрованном диске.

Чего в копии **нет**: ни паролей и ключей из `.env` (`JWT_SECRET`, ключ Firebase, пароль от базы), ни адреса базы — проверено поиском по содержимому. Есть только имя пользователя базы (не пароль).

### Если сработал автоматический выбор адреса

Сервер ходит в Neon через «пулер» (в адресе `-pooler`), а для копии лучше прямой адрес — скрипт сам убирает `-pooler` и пишет об этом строку `Note: …`. Если после этого вход не удаётся (ошибка подключения к `…`), возьмите в консоли Neon строку **Direct connection** (без пулера) и передайте её явно:

```bash
BACKUP_DATABASE_URL='postgresql://…' npm run backup
```

## Восстановить в чистую базу

Скрипт восстанавливает **только в пустую базу**: непустую он не принимает и ничего не стирает. Поэтому сначала создайте новую.

1. **Новая пустая база.** В консоли Neon создайте новую базу (или новый проект) и скопируйте её строку **Direct connection** (без `-pooler`).
2. **Восстановить:**
   ```bash
   RESTORE_DATABASE_URL='postgresql://…строка из шага 1…' npm run restore -- ~/nook-backups/nook-ДАТА-ВРЕМЯ.dump
   ```
   Если `RESTORE_DATABASE_URL` не задана, скрипт спросит адрес (ввод скрыт). Это всё-или-ничего: при любой ошибке база остаётся пустой.
3. **Проверить сообщение в конце.** Должно быть: `OK: all tables have the same number of rows as the original`. Если там `DIFFERENT` — числа строк не совпали, такой базе не верить (небольшая разница возможна, только если в момент копии приложением пользовались; тогда сделайте копию заново).
4. **Переключить сервер на новую базу.** Render → сервис → Environment → `DATABASE_URL` = строка новой базы **через пулер** (как была у старой, с `-pooler`) → Save, дождитесь перезапуска. Миграции при старте ничего не изменят: они уже записаны в копии.
5. **Проверить.** Войти в приложении (или `POST /auth/login`), открыть задачи и дневник.

Старую базу не удаляйте, пока не убедитесь, что новая работает.

## Что делать при ошибке

| Что случилось | Что делать |
|---|---|
| Данные испортились или удалились **недавно** (меньше 6 часов) | Откат по истории Neon: в консоли Neon у ветки/базы найдите **Restore** («восстановить на момент времени») и выберите время до ошибки. Названия кнопок в Neon меняются — искать слово Restore. Это самый быстрый путь. |
| Прошло больше 6 часов, или Neon недоступен | Восстановить из своей копии (раздел выше) в новую базу и переключить на неё сервер. |
| Копии нет, а история Neon уже не помнит | Данных уже не вернуть. Поэтому копию стоит делать регулярно (см. «Когда делать»). |

## Частые ошибки скрипта

| Сообщение | Причина |
|---|---|
| `pg_dump is not installed` | нет клиента PostgreSQL, см. «Что понадобится» |
| `the PostgreSQL client is version N` | версия клиента меньше 16 |
| `server version mismatch` (от `pg_dump`) | версия клиента **меньше** версии сервера Neon; поставьте клиент новее |
| `DATABASE_URL is not set` | нет строки в `.env` и нет переменной |
| `password authentication failed` | неверный пароль в строке подключения |
| `the folder is inside the project` | вы указали папку внутри проекта; выберите другую |
| `that database is not empty` | восстанавливать можно только в пустую базу; создайте новую |
| `DIFFERENT` | после восстановления числа строк не совпали; не пользоваться этой базой |

## Что проверено

На локальной базе с реальными данными (12 пользователей, группы, ≈ 660 задач, 3100 отметок, 275 заметок, цикл; 10 МБ): копия → восстановление в пустую базу → число строк и **содержимое всех 17 таблиц** совпали, схема (таблицы, индексы, ограничения, триггеры) совпала, 8 стартовых настроений на месте, на восстановленной базе настоящий сервер принял вход, отдал `pull` и принял `push`. С настоящим Neon скрипт пока не пробовался — это проверка владелицы.
